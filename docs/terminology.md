# Studio 용어와 도메인 경계

이 문서는 Studio의 사용자 화면, API 설명, 에이전트 도구가 사용하는 용어의 기준이다.
일반적인 음악 파일 묶음이나 편집기 저장 파일을 무조건 프로젝트라고 부르지 않는다.

| 용어 | 정의 | 다른 개념과의 관계 |
| --- | --- | --- |
| 곡 · Song | 프로젝트와 채보의 배경음으로 사용하는 음악과 그 식별 정보 | 하나의 곡을 여러 프로젝트와 채보에서 사용할 수 있다. 곡 자체는 생성 규칙이나 노트 배열이 아니다. |
| 프로젝트 · Project | 채보를 생성하기 위한 규칙과 구성요소의 모음 | 사용할 곡과 Single/Double 모드를 명시하고, 생성에 사용하는 규칙을 편집·저장한다. 프로젝트와 생성된 결과물은 구분한다. |
| 채보 · Chart | 프로젝트에서 생성한 결과물인 개별 노트 구성 | 탭·동시 입력·홀드의 위치와 길이를 가진다. 프로젝트의 규칙을 바꿔도 이미 생성된 채보를 소급해서 변경하지 않는다. |
| 라이브러리 · Library | 여러 프로젝트에서 공유할 수 있도록 재사용 가능하게 만든 구성요소의 모음 | 프로젝트의 구성요소를 라이브러리에 공개하고 다른 프로젝트에서 가져와 재사용한다. 단순한 곡·채보 파일 목록의 동의어가 아니다. |

## 관계

```text
곡: 배경음 ───────────────┐
                         ▼
라이브러리 구성요소 ──→ 프로젝트: 모드 + 생성 규칙 ──→ 채보 A
                         │                       └─→ 채보 B
                         └─ 구성요소를 재사용 가능하게 만들기 ──→ 라이브러리
```

## 모드

- Single은 한 패드의 다섯 레인, Double은 두 패드의 열 레인을 사용한다.
- 모드는 프로젝트를 만들 때 반드시 선택한다. 생성된 채보는 그 모드를 따른다.
- Single/Double은 단순한 UCS 내보내기 옵션이 아니라 생성·편집·저장·검증의 제약이다.
- 모드가 다른 결과물을 만들려면 해당 모드의 프로젝트를 사용한다. 기존 노트를 조용히
  잘라 내거나, 모드를 바꾸는 것만으로 다른 형식으로 변환됐다고 간주하지 않는다.

## 에이전트의 작업 대상

에이전트가 프로젝트를 읽는다는 것은 실제 저장된 생성 규칙과 구성요소를 읽는 것이다.
프로젝트를 쓴다는 것은 검증과 리비전 충돌 검사를 거쳐 그 규칙을 저장하는 것이다.
채보 제안만 생성하거나 자연어로 변경했다고 말하는 것은 프로젝트 쓰기가 아니다.

곡의 음원 파일, 원본 ZIP, 채보 결과물, 프로젝트 규칙, 라이브러리 구성요소는 서로
다른 자원이다. 프로젝트 쓰기 권한은 임의 파일 시스템·셸·자격 증명 접근 권한을 뜻하지 않는다.
